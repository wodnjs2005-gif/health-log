# 나의 건강일지

복지관 이용자(어르신·유소년)가 휴대폰으로 **운동·식사를 기록**하고, 트레이너가 올린 **운동 영상을 따라하는** 웹앱입니다.

| 역할 | 들어가는 방법 | 할 수 있는 일 |
| --- | --- | --- |
| 이용자 | 6자리 개인 번호 | 내 운동·식사 기록, 배정된 운동 영상 따라하기 |
| 보호자 | 6자리 보호자 번호 | 가족의 식사·운동 기록 **보기만** |
| 트레이너 | 8자리 트레이너 번호 | 이용자 기록 확인, 해시태그, 운동 영상 등록·대상 지정 |
| 관리자 | 아이디 + 비밀번호 | 이용자·트레이너 등록과 번호 발급, 해시태그, 운동 영상 |

- Vite + React + TypeScript, CSS Modules (모든 크기는 rem → 「글자 크기」 버튼으로 전체가 커집니다)
- 백엔드: **Supabase (Postgres + Storage)**. 테이블에 직접 접근하지 않고 **RPC 함수로만** 접근합니다.
- Supabase 연결이 꼭 필요합니다. 설정 없이 배포하면 「서버 연결 설정이 필요해요」 화면만 나옵니다.

## 1. Supabase 설정 (약 15분)

1. https://supabase.com 가입 → **New project** 생성 (지역: Northeast Asia (Seoul) 권장)
2. **데이터베이스 만들기**
   - **새 프로젝트라면**: 왼쪽 메뉴 **SQL Editor** 에 `supabase/setup_all.sql` 내용을 통째로 붙여넣고 **Run** 한 번이면 끝입니다.
     (아래 9개 파일을 순서대로 합친 파일이며, `npm run build:sql` 로 다시 만들 수 있습니다)
     여러 번 Run 해도 되고, 이미 쓰던 데이터베이스에 실행해도 표·기록은 지워지지 않습니다(함수만 새로 만듭니다).
     오른쪽 아래에 **Success. No rows returned** 가 나와야 성공입니다. 빨간 오류가 나면 전체가 취소된 것입니다.
   - **이미 쓰던 데이터베이스라면**: `supabase/migrations/` 의 파일 중 아직 실행하지 않은 것만 **이름 순서대로** 하나씩 붙여넣고 **Run** 합니다.

   | 순서 | 파일 | 내용 |
   | --- | --- | --- |
   | 1 | `20260925000000_healthlog_init.sql` | 기본 표·함수·영상 저장소 |
   | 2 | `20260926000000_guardian.sql` | 보호자 번호 |
   | 3 | `20260927000000_birthdate.sql` | 생년월일 |
   | 4 | `20260928000000_set_birth.sql` | 기존 이용자 생년월일 입력 |
   | 5 | `20260929000000_tags_programs.sql` | 해시태그, 영상 대상 고르기 |
   | 6 | `20260930000000_program_members.sql` | 영상 대상 이용자 수정 |
   | 7 | `20261001000000_staff_accounts.sql` | **관리자 로그인, 트레이너 번호** |
   | 8 | `20261002000000_trainer_rank.sql` | 트레이너 직급 |
   | 9 | `20261003000000_lessons_attendance.sql` | 수업과 출석 |

   Supabase CLI를 쓴다면 `supabase link --project-ref <프로젝트 ID>` → `supabase db push` 로 한 번에 실행됩니다.
   이미 쓰고 있던 데이터베이스라면 아직 실행하지 않은 파일만 순서대로 실행하면 되고, 기존 기록은 지워지지 않습니다.

3. **첫 관리자 계정 만들기** (꼭 필요): SQL Editor에서 아이디·비밀번호를 바꿔서 실행합니다.

   ```sql
   select admin_create('admin', '여기에-8자-이상-비밀번호', '관리자');
   ```

   - 아이디는 3자 이상, 비밀번호는 8자 이상입니다. 영문 대소문자·숫자·기호를 섞어 길게 정하세요.
   - 관리자가 여러 명이면 아이디를 바꿔 여러 번 실행합니다.
   - **비밀번호를 잊었을 때**도 같은 명령을 다시 실행하면 그 아이디의 비밀번호가 새로 정해지고, 잠금도 풀립니다.
   - 이 명령은 SQL Editor에서만 실행할 수 있고, 앱에서는 부를 수 없습니다.

4. **Project Settings → API** 에서 `Project URL`과 `anon public`(또는 `publishable`) 키를 복사합니다.

## 2. 내 컴퓨터에서 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다.

- `.env` 가 있으면 그 Supabase에 연결됩니다.
- `.env` 가 없으면 **개발용 가짜 서버**로 열립니다. `npm run dev` 에서만 쓰이고 배포용 빌드에는 들어가지 않습니다.
  데이터는 그 브라우저에만 저장되며, 로그인 화면 아래에 개발용 번호·관리자 계정(`admin` / `admin1234`)이 보입니다.

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run build` | 타입 검사 + `dist/` 에 배포용 파일 만들기 |
| `npm run preview` | 만든 `dist/` 미리 보기 |
| `npm run build:html` | 파일 하나짜리 `../나의 건강일지.html` 만들기 (`.env` 필요) |
| `npm run test:export` | 가상의 데이터로 엑셀 내려받기 파일을 만들어 `export-test/` 에 저장 (양식 점검용) |

### 파일 하나로 열어보기

`.env` 를 넣은 뒤 `npm run build:html` 을 실행하면 프로젝트 바깥 폴더에 **`나의 건강일지.html`** 이 생깁니다.
더블클릭하면 크롬·엣지에서 열리고, 설정한 Supabase에 연결됩니다. 유튜브 영상은 파일로 열었을 때 재생되지 않을 수 있으니
실제 사용은 배포한 주소를 쓰세요. (엑셀 내려받기도 배포한 주소에서만 됩니다)

## 3. 환경변수

프로젝트 폴더에 `.env` 파일을 만들고(`.env.example` 복사) 값을 넣습니다.

```bash
VITE_SUPABASE_URL=https://abcdefgh.supabase.co
VITE_SUPABASE_KEY=eyJ...   # anon(public) 키 또는 sb_publishable_... 키
```

| 이름 | 설명 |
| --- | --- |
| `VITE_SUPABASE_URL` | Supabase Project URL |
| `VITE_SUPABASE_KEY` | anon(public) 또는 publishable 키. **service_role 키는 절대 넣지 마세요.** |

값은 빌드할 때 앱에 들어가므로, 바꾼 뒤에는 다시 빌드(배포)해야 합니다.

## 4. 배포 (인터넷 주소 만들기)

정적 사이트라서 Netlify나 Vercel에 무료로 올릴 수 있습니다. 두 곳 모두 설정 파일(`netlify.toml`, `vercel.json`)이 들어 있습니다.

### Netlify
1. 이 폴더를 GitHub 저장소에 올립니다. (`.env` 는 올라가지 않게 `.gitignore` 에 들어 있습니다)
2. https://app.netlify.com → **Add new site → Import an existing project** → 저장소 선택
3. 빌드 설정은 자동으로 채워집니다(Build command `npm run build`, Publish directory `dist`).
4. **Site configuration → Environment variables** 에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_KEY`를 넣고 **Deploy**

GitHub 없이 올리려면: 내 컴퓨터에서 `.env`를 넣고 `npm run build` → 생긴 `dist` 폴더를 https://app.netlify.com/drop 에 끌어다 놓습니다.

### Vercel
**GitHub로 올리는 경우** (코드를 고칠 때마다 자동으로 다시 배포됨)
1. https://vercel.com → **Add New → Project** → 저장소 선택 (Framework: Vite)
2. **Environment Variables** 에 두 값을 넣고 **Deploy**

**GitHub 없이 내 컴퓨터에서 바로 올리는 경우**
1. 프로젝트 폴더에서 `npx vercel login` → 이메일 등으로 로그인
2. `npx vercel` → 질문에는 모두 Enter (처음 한 번은 프로젝트가 만들어짐)
3. https://vercel.com 의 그 프로젝트 → **Settings → Environment Variables** 에 두 값을 넣음
4. `npx vercel --prod` → 마지막에 나오는 `https://….vercel.app` 주소가 실제 주소입니다.
   이후 코드를 고치면 `npx vercel --prod` 만 다시 실행하면 됩니다.

만들어진 주소를 이용자에게 알려주세요. 휴대폰에서 **「홈 화면에 추가」** 하면 앱처럼 쓸 수 있습니다.

### 배포 후 처음 할 일
1. **관리자** 버튼 → 1-3 에서 만든 아이디·비밀번호로 로그인
2. **트레이너 관리** 탭 → 트레이너 등록 → 나온 **8자리 트레이너 번호**를 트레이너에게 전달
3. **이용자 관리** 탭 → 이용자 등록 → 나온 **개인 번호**는 이용자에게, **보호자 번호**는 가족에게 전달

## 5. 사용 흐름

- **관리자**: 아이디·비밀번호로 로그인합니다. 위쪽 **이용자 관리 / 트레이너 관리 / 출석 / 운동 영상** 으로 바꿔 가며 씁니다.
  - **이용자 관리**: 이용자 등록(이름 + 생년월일 + 해시태그(선택)) → 6자리 개인 번호와 보호자 번호가 발급됩니다.
    나이는 생년월일로 오늘 기준 **만 나이**를 자동 계산합니다. 카드에서 생년월일 수정, 해시태그, 새 번호 발급, 삭제를 합니다.
  - **트레이너 관리**: 트레이너 등록(이름 + 직급(선택), 예: 팀장·선임 트레이너) → **8자리 트레이너 번호**가 발급됩니다.
    번호를 잃어버렸거나 그만둔 경우 **새 번호 발급** 또는 **트레이너 삭제**를 두 번 누르세요. 바로 그 트레이너의 로그인이 끝납니다.
  - **출석**, **운동 영상**: 트레이너와 같은 화면입니다.
  - 아래 **비밀번호 변경**으로 비밀번호를 바꿀 수 있습니다. 바꾸면 다른 기기의 관리자 로그인은 끝납니다.
- **트레이너**: 받은 8자리 번호로 들어갑니다(한 번 들어가면 30일 동안 다시 묻지 않음).
  이용자별 이번 주 운동량과 식사 기록을 보고, 해시태그를 달고, **운동 영상**(파일 또는 유튜브 링크)을 등록합니다.
  - 영상을 등록할 때 **대상 이용자**를 이름·초성(예: ㄱㅅㅈ)·#해시태그로 찾아 고르면, **고른 분들만** 그 영상을 볼 수 있습니다.
    해시태그를 누르고 「찾은 분들 모두 고르기」로 반 전체를 한 번에 고를 수 있습니다.
  - 이미 등록한 영상은 카드의 **대상 이용자 수정**으로 대상을 바꿉니다. 뺀 분은 더 이상 볼 수 없지만, 이미 따라한 기록은 남습니다.
  - 이용자가 영상을 건너뛰지 않고 90% 이상 보면 따라한 횟수와 운동일지가 자동으로 기록됩니다.
- **출석(트레이너·관리자)**: **출석** 탭 → **+ 수업 만들기**(수업 이름, 요일, 대상 이용자) → 수업을 누르면 오늘 출석부가 나옵니다.
  - 이름을 누르면 **출석**, 다시 누르면 **결석**. **‹ 날짜 ›** 로 지난 날도 고칠 수 있습니다(내일 이후는 안 됨).
  - 쉬는 날은 **이 날 휴강**을 누르면 출석률 계산에서 빠집니다. 수업 요일이 아닌 날 체크하면 보강으로 기록됩니다.
  - 출석률은 **수업 요일 중 대상에 들어간 날부터** 셉니다. 대상에서 뺀 분의 지난 출석 기록은 남습니다.
  - 이용자 본인(홈 화면)과 보호자는 **수업 출석** 카드에서 이번 달 출석과 최근 수업일을 봅니다. 다른 이용자의 출석은 보이지 않습니다.
- **이용자**: **이용자** 버튼 → 받은 번호 입력(6자리를 다 넣으면 바로 들어감) → 본인 기록만 보입니다.
  한 번 들어가면 그 휴대폰에서는 다시 묻지 않습니다.
- **보호자(가족)**: **보호자** 버튼 → 관리자에게 받은 **보호자 번호** 입력 → 가족의 기록을 봅니다.
  - 위쪽 **‹ 날짜 ›** 로 하루씩 넘겨 지난 기록을 봅니다. 그래프 막대를 눌러도 그 날로 갑니다.
  - **보기만 가능**합니다. 기록을 추가·삭제할 수 없고, 이용자의 개인 번호도 보이지 않습니다.
  - 자녀 둘, 부모님 두 분처럼 **여러 명**을 볼 수 있습니다(「+ 다른 분 추가」).
- **기록 내려받기(관리자·트레이너)**: 이용자 목록 위 **엑셀 내려받기**, 또는 이용자 카드·상세의 **기록 내려받기**.
  - 대상(**전체 이용자** 또는 **한 명**)과 기간(이번 달·지난달·최근 7일·최근 30일, 또는 시작일~종료일)을 고르면 엑셀 파일이 저장됩니다.
  - 시트 4개: **요약**(이용자별 운동 횟수·시간, 영상 따라하기, 끼니별 식사 수, 수업 출석률) · **운동 기록** · **식사 기록** · **출석**(수업별 ○/× 출석부).
  - 요약의 숫자는 엑셀 수식이라 기록 시트를 고치면 함께 바뀝니다. A4 가로로 인쇄되도록 맞춰 두었습니다.
  - 파일은 휴대폰·컴퓨터 안에서 만들어지며 서버에는 저장되지 않습니다.
- **해시태그(관리자·트레이너)**: #오전반, #무릎조심처럼 구분 표시를 달고, 목록 위 해시태그 버튼으로 골라 봅니다.
  직원 화면에만 보이며 이용자·보호자 화면에는 나오지 않습니다.

## 6. 보안

- **관리자**: 비밀번호는 bcrypt로 암호화해 저장합니다. **5번 틀리면 10분 동안 잠깁니다.**
  로그인하면 비밀번호 대신 **12시간짜리 로그인 표(세션)** 만 기기에 남고, 서버에는 그 표의 해시만 저장됩니다.
- **트레이너**: 8자리 번호(약 8,500억 가지)로 로그인하고, **30일짜리 로그인 표**를 받습니다.
  새 번호를 발급하거나 삭제하면 그 트레이너의 로그인 표는 모두 끝납니다.
- **권한**: 이용자·트레이너 등록, 번호 발급, 생년월일 수정은 **관리자 로그인 표로만** 됩니다(서버 함수 안에서 확인).
  트레이너 화면에는 이용자의 개인·보호자 번호가 내려가지 않습니다.
- **이용자·보호자**: 본인(가족) 기록과 배정된 영상만 볼 수 있습니다(서버 함수 안에서 번호로 확인). 보호자 함수는 읽기만 합니다.
- 번호에는 헷갈리는 글자(0·O, 1·I·L)를 쓰지 않습니다. 입력할 때 소문자·띄어쓰기·하이픈은 자동으로 정리합니다.
- 예전 버전의 **트레이너·관리자 공용 비밀번호**는 7번 파일을 실행하면 없어지고, 기기에 남은 예전 비밀번호도 앱을 열 때 지웁니다.

### 알아두세요
- 이용자 번호(6자리)에는 잠금 기능이 없습니다. 번호가 알려졌다면 관리자 화면에서 **새 번호 발급**을 해주세요.
- 영상 파일 저장소(`videos` 버킷)는 앱 키만 있으면 업로드할 수 있게 열려 있습니다.
  앱은 올리기 전에 로그인 표를 확인하지만, 저장소 자체를 막지는 못합니다. 걱정되면 파일 대신 유튜브 링크만 쓰고,
  Supabase **Storage → Policies** 에서 `healthlog video upload` 정책을 지우세요.
- 영상 파일은 Supabase 무료 요금제 기준 **파일당 50MB**까지 올릴 수 있습니다. 영상을 삭제해도 저장소 파일은 남으니 필요하면 **Storage → videos** 에서 지우세요.
- 퍼가기가 막힌 유튜브 영상은 재생되지 않습니다.
